# Standards

Standards documents define the contract surfaces the Release Package Program enforces. Each catalog repo's adoption CR cites the relevant standards.

## Available Standards

| Standard | Status | Owner | Purpose |
|---|---|---|---|
| [bpmn-profile.md](./bpmn-profile.md) | Planned | CR-DEA-RP-02 §6 | BPMN 2.0 profile for process catalog plugin files |
| [archimate-profile.md](./archimate-profile.md) | Planned | CR-DEA-RP-02 §7 | ArchiMate 3.2 profile for capability catalog plugin files |
| [release-package-shape.md](./release-package-shape.md) | Planned | CR-DEA-RP-01 §4 | Canonical asset list and naming for every release package |
| [registry-schema.md](./registry-schema.md) | Planned | CR-DEA-RP-02 §4 | Manifest schema (registry-schema@v1) |

## Status Definitions

- **Planned** : committed in a CR but not yet drafted as a standalone standard.
- **Draft** : first revision, accepting feedback.
- **Final** : accepted and frozen; changes require a new CR.

## Contribution

Each standard is owned by a CR. Updates to a standard require the CR to be amended or a new CR to land. Standards never evolve in-place without a CR trace.
